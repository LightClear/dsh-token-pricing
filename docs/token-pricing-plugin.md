# Token Pricing 插件介绍

`@deepseek-ai/dsh-client-token-pricing` 是 DeepSeek Harness Web 界面的**模型 token 定价插件**。它让你按提供方/模型配置每百万 token 的美元价格——输入缓存未命中、输入缓存命中、输出，以及可在任意多个高峰时段生效的高峰价格档——然后在三个界面表面上实时查看会话费用：对话框底部的数据栏、设置页里的「模型定价」、以及一个可折叠可拖拽的费用浮窗（支持「按轮计价」与「按模型计价」两种视图）。

一句话概括：**配置一次价格，之后每个会话的每一轮、每个模型花了多少钱，都能在界面上直接看到。**

## 它解决什么问题

在按 token 计费的 LLM 世界里，「这个会话到底花了多少钱」是一个高频却难以回答的问题：用量分散在多轮、多个模型之间，缓存命中与未命中的价格不同，高峰时段的费率也可能不同。没有统一的价格配置与聚合读数，用户只能靠人工估算或事后查账单。

这个插件把三件事收拢到一处：

1. **一处配置价格** —— 在设置页为每个提供方/模型维护一套费率，包括缓存命中/未命中的输入价、输出价，以及可选的高峰价格档。
2. **一处派生用量** —— 不单独存用量，而是从会话的持久事件日志折叠出逐步的 token 用量事实。
3. **三处展示费用** —— 数据栏给最精简的总数，浮窗给按轮/按模型的明细，设置页给价格编辑。

## 三个界面表面

### 设置页：模型定价

![设置页：展示具体模型的设置页面，读取已设置的模型配置，并配置模型价格与高峰期计价规则](settings-page.png)

设置 → 模型定价 把模型目录按提供方分组为卡片，每个模型带一个已配置/未配置圆点。展开某个模型打开编辑器，自动载入已存配置，可编辑三档基础费率（输入未命中、输入命中、输出，单位美元/每百万 token）以及高峰期计价规则。

启用高峰定价后，可按需增删任意多个高峰时段，全部时段共享一套高峰费率。默认只有一段，时段支持跨午夜（例如 22:00–08:00），并可在本地时间与 UTC 之间选择；当前时间落入任一时段即按高峰价计费。

### 底部数据栏：实时费用

![会话底部数据栏：展示对话框底部数据区域的计价数据](bottom-data-view.png)

对话框底部数据栏在出厂统计行旁显示会话的 `输入 $X · 输出 $Y · 总计 $Z`。每一步按自身时间、在其派发路由下计价，读数对每个已计价步骤求和，因此与浮窗总计永远一致；未配置计价路由的用量不计入该数字。

数据栏刻意保持最简：不显示模型名、不显示高峰/非高峰徽标——按轮与按模型的明细交给浮窗。

### 费用浮窗：折叠、展开、拖拽

![费用浮窗折叠态：右下角小球显示会话总费用](floating-window-folded.png)

折叠态是一个小球，显示当前会话的累计费用；点击小球展开面板。

![费用浮窗展开态：完整窗口，含标题栏、视图切换与底部总计](floating-window-expanded.png)

展开态面板包含两个视图切换页签与底部总计栏。小球、标题栏（顶部）与总计栏（底部）都是拖拽区域；展开态顶部锚定、底部延展，切换视图或内容增长时移动的是底边而不是标题栏。

#### 按轮计价

![费用浮窗的按轮计价页面](floating-window-turn.png)

「按轮计价」按对话轮次列出每轮（轮次号与开始时间）使用的路由、token 数与费用；一轮中途切换模型时按路由拆分为多行。

#### 按模型计价

![费用浮窗的按模型计价页面](floating-window-model.png)

「按模型计价」按会话中使用过的所有模型聚合 token 数与费用，按首次使用顺序排列。两种视图中，未配置计价规则的模型仍显示 token 数并提示 `未设置计价`。

## 计价模型

### 费率

每个模型条目维护三档基础费率（美元/每百万 token）：

| 字段 | 含义 |
| --- | --- |
| 输入（未命中） | 未命中缓存的输入 token 价格 |
| 输入（缓存命中） | 命中缓存的输入 token 价格 |
| 输出 | 输出 token 价格 |

计费口径遵循 DeepSeek 语义：**缓存写入按缓存未命中价计费**。因此一条条目的输入费用为：

```
输入费用 = (未缓存输入 + 缓存写入) × 未命中价 + 缓存读取 × 命中价
```

### 高峰价格档

每个条目可额外启用一套高峰价格档（高峰输入未命中/命中、高峰输出），并关联任意多个高峰时段。判定规则：

- 时段用 `[start, end)` 表示墙钟时间；结束早于开始即跨午夜（22:00–08:00 覆盖两段）；零长度时段覆盖全天。
- 时段的时区基准可选本地时间或 UTC。
- 某一步的时间落入条目的**任一** `peakWindows`，该步即按高峰价计费；否则按基础价。

这意味着一个条目可以声明多个互不重叠的高峰时段（如早晚两个高峰），而高峰/非高峰的判定是按**每一步自身的时刻**进行的，而不是按「现在」统一结算——这与「事后修改价格会按新价重算历史」一起，构成了下文要讲的一致性基石。

## 数据从哪来：`tokenPricing` 投影

按轮用量**不是单独存储的**。`tokenPricing` 投影把会话的持久事件日志折叠为逐步的用量事实：

- 每条携带服务商上报 `usage` 的 `assistant/message`，盖上它的派发路由（最近一条 `request/header` 的 `config.provider`/`config.model`）与该步自身的时间戳。
- 只记录用量事实（输入/缓存读/缓存写/输出四桶 token 数、路由、时间、轮次），**不记录任何费率或美元金额**。

这种设计带来两个关键性质：

1. **随会话持久化** —— 折叠重放日志，数据随会话持久化、重启后还原，并随归档的会话一并保留（归档只隐藏列表行，从不改写日志）。
2. **事后改价重算历史** —— 费率住在设置作用域里，浏览器在渲染时逐步计价；因此修改价格条目会按新价重算所有历史步骤，无需迁移任何历史金额数据。

高峰/非高峰也按每步自身时间判定：某步的时间落入其条目任一 `peakWindows` 即按高峰价计费。

## 架构与代码结构

插件分两个半身，职责清晰：

| 半身 | 文件 | 职责 |
| --- | --- | --- |
| node（Host） | `src/index.ts` | 注册持久化设置命名空间（`token-pricing` 段）+ 注册 `tokenPricing` 投影单元 |
| node（Host） | `src/settings.ts` | 设置命名空间的 schema（多时段 + 旧单时段迁移 transform） |
| node（Host） | `src/projection.ts` | 会话日志折叠为逐步用量事实（路由归属 + 轮次分组） |
| node（Host） | `src/types.ts` | `tokenPricing` 投影视图类型 + `SessionProjectionMap` 合并 |
| 浏览器 | `src/client/pricing.ts` | 纯费用计算（多时段判定/路由匹配/逐步计价/按轮按模型聚合/格式化） |
| 浏览器 | `src/client/PricingDock.tsx` | 会话底部数据栏读数（仅费用，无模型名） |
| 浏览器 | `src/client/PricingFloat.tsx` | 浮窗（折叠球 + 展开面板、拖拽、顶部锚定） |
| 浏览器 | `src/client/PricingSection.tsx` | 设置页（模型页风格、多时段编辑器） |
| 通用 | `src/invariant.ts` | 包 invariant 伴随件 |

三个设计要点值得强调：

1. **纯计算与投影分离** —— `pricing.ts` 是纯函数集合，不依赖 React，也不携带框架；数据栏、浮窗、设置页预览共享同一套计价逻辑，单元测试无需渲染机制即可驱动它。投影只携带用量事实，费率住在设置作用域，因此所有消费方以完全相同的方式计价。
2. **兼容迁移内置在 schema 里** —— 旧版单时段条目（`peakStart`/`peakEnd`）在读取时通过 schemastery transform 自动折叠为 `peakWindows`，旧配置在 schema 升级后仍然有效。
3. **复用既有 Host 服务** —— 插件不新增任何 Host RPC：设置走 `settings` 服务，投影走 `sessionProjections` 注册表，模型目录走既有的 `llm.models` RPC。node 半身只注册命名空间与投影单元，其余全部复用现有服务。

## 三个表面为何永远一致

数据栏、浮窗（两种视图）、设置页预览都调用 `pricing.ts` 里的同一套纯函数：`priceStep`（按步计价）→ `aggregateByTurn`（按轮聚合）/ `aggregateByModel`（按模型聚合）→ `totalsOf`（求和）。因此三个表面的总计不可能互相矛盾；数据栏读数是「对每个已计价步骤求和」，而浮窗总计也是同样一组步骤的和。

唯一的差异是**覆盖范围**：数据栏只覆盖已配置计价路由的用量，未配置的路由不贡献数据栏数字；而浮窗的按模型视图会把未配置路由的 token 数显示出来，并标注 `未设置计价`。

## 与模型的隔离

本插件对模型请求**零侵入**：

- **模型看到的内容** —— 不注册任何工具、不注册提示段，也没有任何设置值进入请求路径；数据栏、浮窗与设置页只呈现线上已有的持久数据（`tokenPricing` 投影值与 `token-pricing` 设置段）。
- **Token 影响** —— 零：不添加、移除或改动任何提示内容、工具 schema 或消息。
- **KV Cache 影响** —— 无：请求组成、缓存复用与压缩均不受影响；`tokenPricing` 折叠只在请求提交后运行。

## 安装与使用

本仓库是 `@deepseek-ai/dsh-client-token-pricing` 的源码存档，运行时与构建依赖 [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) 主仓库（内部 `@deepseek-ai/dsh-*` 均为 `workspace:^` 引用）。推荐做法是把 `src/`、`tests/` 与配置文件复制到 `packages/client/token-pricing/` 并应用 `harness-integration.patch`，详见 [INTEGRATION.md](../INTEGRATION.md)。

配置完成后：

1. 打开 设置 → 模型定价，为各提供方/模型配置价格；价格持久化在 `$DSH_HOME/settings.yaml`。
2. 回到对话界面，底部数据栏即显示会话费用；点击右下角小球展开浮窗，切换按轮/按模型视图查看明细。

## 已知限制

- **压缩摘要不计费** —— 压缩步骤自身的模型调用不追加 usage 事件，其费用不出现在任何数字中（与 `tokenUsage` 计量口径一致）。
- **无服务商用量的步骤不计费** —— 未上报计费的适配器调用、或消息组装前中止的步骤不产生记录行。
- **浮窗位置每次加载重置** —— 拖拽位置保存在组件状态里，刷新页面后回到默认位置。
- **数据栏数字只覆盖已配置路由** —— 未配置计价路由的用量不贡献数据栏总计；这部分用量在浮窗的按模型视图中显示为未计价。
